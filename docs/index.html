能看什么

监控数据全部来自系统内核接口，不装第三方依赖。

硬件监控

CPU 占用率、内存占用和组成、磁盘剩余、网络上下行速率、屏幕亮度。

电池

电量、健康度、循环次数、充电状态、电池温度，一块电池的状况全在这。

趋势图

温度、CPU、内存、网络四条历史曲线，随时间滚动更新，一眼看出趋势。

告警

温度、CPU、内存、磁盘、电量超过阈值触发系统通知和提示音，菜单栏图标变红。

悬浮小窗

无边框置顶小窗，按住就能拖动，随时瞄一眼，深浅色自动适配。

效率工具

剪贴板历史、系统信息一键复制、二维码、单位换算、编码、番茄钟、便签，顺手加进来的。

技术上的几个选择

写这个小东西踩过的坑，也顺便记录在这。

温度走 HID，不走 SMC

Apple Silicon 上芯片温度其实挂在 HID 传感器集线器（usagePage 0xFF00）里，PMU tdie/tdev、NAND、电池一共 45 个传感器。普通权限就能读，CPU 温度取 tdie 最大值。私有 API 没进 SDK，用 dlopen 动态调用。

风扇为什么读不到

M 系列上只有 SMC 有 F*Ac 这类 key，新版 macOS 对普通进程直接拒绝。像 BuhoCleaner 能显示风扇，是因为它内置了一个需要开发者证书签名的 root 特权助手，普通 App 装不了。SMC 协议代码写好了，系统放开接口就能恢复。

纯 SwiftUI，无三方依赖

界面原生 SwiftUI，图表用 Swift Charts，数据全是系统接口。进程 CPU 百分比按核心数归一化，还做了平台无关的自动校准，换个系统版本也不用改代码。

一个插曲：Xcode 27 beta 的 Swift 宏系统是坏的，@Observable 和 @State 全报错，工程统一用了 ObservableObject 绕开。代码里注释都写清楚了。

怎么用

两种方式，任选。

# 方式一：命令行构建
./build.sh
open build/Build/Products/Debug/HardwareMonitor.app

# 方式二：Xcode 直接跑
打开 HardwareMonitor.xcodeproj，选 My Mac，⌘R

菜单栏会多一个温度计图标，点开就是概览面板。首次使用弹通知权限时点允许，告警要用。
